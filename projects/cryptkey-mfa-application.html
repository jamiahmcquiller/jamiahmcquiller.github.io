CryptKey — MFA Application

CryptKey is a team-based academic project built with Python and Flask to explore authentication workflows and multi-factor authentication concepts. The project focused on time-based one-time passwords, QR-code login, user registration, security-key management, and validation workflows.

Project Overview

CryptKey was developed as a team-based academic cybersecurity project to explore how additional authentication factors can help protect user accounts. The application brought together a web interface and authentication-related backend functionality using Python and Flask.

Development included designing user-facing authentication screens, implementing registration and validation workflows, generating time-based authentication codes, and exploring QR-code-based account setup.

Project objective: Explore practical MFA implementation, connect frontend and backend workflows, and identify the security and testing considerations involved in building an authentication application.

Security Problem

Password-only authentication can leave accounts exposed when credentials are stolen, reused, or disclosed through phishing. Multi-factor authentication adds another verification step, but implementing it securely requires careful handling of authentication secrets, validation logic, user sessions, and communication.

CryptKey provided a way to examine these challenges through a practical application. The project emphasized the relationship between usability and security, including clear user flows for registering accounts, setting up QR-code login, and validating authentication codes.

Features and Implementation

User Registration

Developed a registration workflow and connected the user-facing interface with backend functionality for onboarding users.

TOTP Generation

Integrated the pyotp library to generate time-based one-time passwords and support authentication code validation.

QR-Code Login

The application generates a QR code encoding a login key, validated server-side. Camera-based QR-code scanning was not implemented in the committed code.

Security-Key Management

Implemented functionality to generate unique security keys, display them in a read-only format, and provide a copy-to-clipboard option.

Authentication Workflows

Developed login, QR-code login, and validation screens to explore the interaction between authentication interfaces and backend processing.

UI/UX Design

Designed application screens for navigation, account management, authentication, and security settings with an emphasis on clarity and usability.

Authentication Workflow

The application was organized around a sequence of user and authentication actions. The following summarizes the intended workflow rather than representing a production deployment.

  1. User registration: A user accesses the registration interface and submits the required information.
  2. Authentication setup: The application supports security-key and QR-code workflows for setting up authentication.
  3. Code generation: TOTP functionality generates time-based codes from authentication secrets.
  4. Validation: The application checks submitted codes or QR-related authentication information through its validation workflow.
  5. Testing and refinement: Individual components and their integration are evaluated to identify issues in QR-code login, validation, and usability.

Security consideration: TOTP implementations depend on protecting the underlying shared secret. Generating a valid code alone does not establish that an entire authentication system is secure.

Testing and Validation

Verified implementation status (checked against the public repository, last commit Dec 16, 2024): CryptKey is a Flask academic prototype with working registration, TOTP generation and validation via pyotp, QR-code login, email verification, and a SocketIO approval flow. Camera-based QR scanning, push notifications, and biometric login were not implemented in the committed code — Touch ID is simulated, and HTTPS/TLS and password hashing remain outstanding. The repository is dormant since December 2024 and is presented here as academic coursework, not a production authenticator.

Testing focused on whether the main authentication components worked together as intended. The committed code contains:

  • User registration and login workflows.
  • TOTP generation and validation via pyotp.
  • QR-code login: the app generates a QR code encoding a login key, validated server-side.
  • Email verification with 6-digit codes.
  • A SocketIO approve/deny authentication flow.

These are prototype features, not the outcome of an independent security audit or a comprehensive test suite. The code does not establish that the application was penetration-tested or production-hardened.

Testing Areas to Consider

  • Valid, invalid, and expired TOTP codes.
  • Incorrect or unreadable QR codes.
  • Registration and authentication error handling.
  • Protection of authentication secrets and user credentials.
  • Session management and access-control checks.
  • Input validation and secure configuration.
