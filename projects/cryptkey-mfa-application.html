Project Overview

CryptKey was developed as a team-based academic cybersecurity project to explore how additional authentication factors can help protect user accounts. The application brought together a web interface and authentication-related backend functionality using Python and Flask.

Development included designing user-facing authentication screens, implementing registration and validation workflows, generating time-based authentication codes, and exploring QR-code-based account setup.

Project objective: Explore practical MFA implementation, connect frontend and backend workflows, and identify the security and testing considerations involved in building an authentication application.

This was an academic prototype, not a production-ready authenticator or a formally audited security product.

Security Problem

Password-only authentication can leave accounts exposed when credentials are stolen, reused, or disclosed through phishing. Multi-factor authentication adds another verification step, but implementing it securely requires careful handling of authentication secrets, validation logic, user sessions, and communication.

CryptKey provided a way to examine these challenges through a practical application. The project emphasized the relationship between usability and security, including clear user flows for registering accounts, scanning QR codes, and validating authentication codes.

Developed login, QR-code login, and validation screens to explore the interaction between authentication interfaces and backend processing.

UI/UX Design

Designed application screens for navigation, account management, authentication, and security settings with an emphasis on clarity and usability.

Authentication Workflow

The application was organized around a sequence of user and authentication actions. The following summarizes the intended workflow rather than representing a production deployment.

  1. User registration: A user accesses the registration interface and submits the required information.
  2. Authentication setup: The application supports security-key and QR-code workflows for setting up authentication.
  3. Code generation: TOTP functionality generates time-based codes from authentication secrets.
  4. Validation: The application checks submitted codes or QR-related authentication information through its validation workflow.
  5. Testing and refinement: Individual components and their integration are evaluated to identify issues in scanning, validation, and usability.
Security consideration: TOTP implementations depend on protecting the underlying shared secret. Generating a valid code alone does not establish that an entire authentication system is secure.

Testing and Validation

Testing focused on whether the main authentication components worked together as intended. The project checkpoint report documented the following preliminary results:

  • User registration functionality was reported as working.
  • TOTP generation and validation were reported as functional.
  • Camera-based QR scanning was reported as operational.
  • The checkpoint report recorded approximately 90% QR-code scanning accuracy in the test cases used.

These are preliminary project-reported results, not the outcome of an independent security audit or a comprehensive test suite. The available checkpoint report does not establish that the application was penetration-tested or production-hardened.

Testing Areas to Consider

  • Valid, invalid, and expired TOTP codes.
  • Incorrect or unreadable QR codes.
  • Registration and authentication error handling.
  • Protection of authentication secrets and user credentials.
  • Session management and access-control checks.
  • Input validation and secure configuration.

Project Takeaway

CryptKey provided hands-on experience connecting web application development with authentication concepts.
